# Конспект аналізу ТЗ проєкту "Student Assistant"

## Функціональні вимоги
Мінімальний набір функцій, спільний для всіх клієнтських модулів проєкту:
* Перегляд переліку навчальних завдань.
* Додавання нового завдання із зазначенням назви (`title`), дедлайну (`dueDate`) та пріоритету (`priority`).
* Позначення завдання як виконаного або невиконаного (`completed`).
* Редагування та видалення існуючих завдань.
* Фільтрація або сортування завдань за станом виконання чи пріоритетом (бажана вимога, не обов'язкова для кожного клієнта).

## Нефункціональні вимоги
* **Кросплатформність:** сукупність усіх клієнтських модулів має покривати операційні системи Windows, macOS та Linux.
* **Гетерогенна архітектура:** система складається з чотирьох незалежно розгортуваних клієнтських модулів без прямих взаємозалежностей один від одного.
* **Різноманітність технологічних підходів:** використання підходів на основі веб-технологій (WebView), AOT-компіляції, віртуальних машин або спільних нативних бібліотек відповідно до тем освітньої компоненти.
* **Процес розробки:** ведення історії змін та розробка здійснюються виключно через Git і GitHub із дотриманням моделі гілок, Pull Request та рецензування коду.

## Модулі та технології

| Модуль | Технологія | Призначення та тема курсу |
|---|---|---|
| `frontend/` | React | Веб-клієнт з адаптивною версткою (Тема 2) |
| `desktop-container/` | Electron / NW.js | Десктопний контейнер, що обгортає веб-інтерфейс (Тема 3) |
| `cpp-core/` | C++ / Qt | Нативний десктопний клієнт (Тема 4) |
| `python-analytics/` | Python / Flet | Аналітичний модуль (Тема 4) |
| `data/` | JSON (`tasks.json`) | Спільний файл обміну даними для всіх клієнтів |

## Формат обміну даними
Обмін даними здійснюється через єдиний спільний файл `data/tasks.json` у корені репозиторію.
Кожен запис — це об'єкт JSON із наступними фіксованими полями:
* `id` — унікальний числовий ідентифікатор завдання (`number`);
* `title` — назва завдання (`string`);
* `completed` — логічний стан виконання (`boolean`: `true` / `false`);
* `dueDate` — дата дедлайну у форматі `РРРР-ММ-ДД` (`string`, наприклад `"2026-10-15"`);
* `priority` — рівень пріоритету (`string`: одне зі значень `"low"`, `"medium"` або `"high"`).

*Примітка:* Жоден клієнт не повинен змінювати перелік чи призначення полів без узгодження.

## Відкриті питання
1. **Блокування та конкурентний доступ:** Як саме має оброблятися ситуація, якщо два клієнти (наприклад, C++ та React) спробують одночасно записати дані у файл `data/tasks.json`?
2. **Відстеження змін у реальному часі:** Чи потрібно реалізовувати автоматичне перечитування файлу `data/tasks.json` (наприклад, через файловий watcher), якщо файл змінено іншим клієнтом?
3. **Обсяг аналітики в Python-модулі:** Які саме конкретні графіки чи статистичні показники (наприклад, відсоток виконаних завдань за тиждень чи розподіл за пріоритетами) очікуються від модуля `python-analytics/`?
